## 进程与执行 Q43–Q46

### Q43 进程与线程的资源边界

**口述：**进程是地址空间与资源组织单位，线程是执行流。一个进程的线程通常共享虚拟地址空间、文件描述符表等，各自有寄存器上下文、栈和线程局部存储。

**机制/边界：**线程自己的栈并非其他线程绝对不可访问，它们仍位于同一个地址空间；错误指针可破坏其他线程数据。多进程通过 IPC 或共享映射协作，隔离通常更强但通信成本和部署复杂度不同。

**追问/验证：**多线程服务崩溃为何常影响整个进程？用线程栈、共享堆和进程地址空间解释，不只答“线程轻量”。

### Q44 fork exec wait 与僵尸

**口述：**fork 创建子进程，父子分别得到返回值；exec 用新程序替换当前进程映像，不是再创建一个新进程；wait/waitpid 回收子进程退出信息。退出但尚未被父进程回收的子进程可成为僵尸。

**机制/边界：**fork 后数据页常通过写时复制共享，文件描述符可指向同一个内核 open file description，因而共享文件偏移。多线程进程 fork 后子进程通常只保留调用线程，继承的锁状态使调用复杂库函数危险，exec 前应遵循相关 async-signal-safe 限制。

**追问/验证：**解释孤儿与僵尸区别，观察 PID/PPID 和状态；不要用“杀掉僵尸进程”替代父进程回收问题分析。

### Q45 用户态与内核态切换

**口述：**系统调用让受控的内核代码执行特权操作，涉及入口/出口、参数检查、上下文状态及可能的数据拷贝。成本取决于操作、缓存和安全机制，而非一个固定纳秒值。

**机制/边界：**一次系统调用不必产生进程切换；只有阻塞、抢占等才可能调度其他线程。减少 syscall 数可降低开销，但过大批量也会增加等待延迟。

**追问/验证：**strace 可以观察调用类型和次数，但追踪本身有开销；对比不追踪的基线，不将追踪时间直接当生产性能。

### Q46 上下文切换保存什么

**口述：**调度切换需要保存/恢复寄存器、程序计数器、栈指针等执行状态；跨进程还涉及地址空间上下文，缓存和 TLB 局部性受影响，具体优化依架构与内核。

**机制/边界：**不是每次切换都把所有内存复制一遍，也不是每次都清空全部缓存。线程数大于硬件并行度本身并不一定差，关键是是否频繁争抢、阻塞和唤醒。

**追问/验证：**结合 CPU 利用率、运行队列、主动/被动切换和锁等待判断；I/O 密集服务的合适并发与 CPU 密集计算不同。

## 内存与文件 Q47–Q51

### Q47 虚拟内存 页表 TLB 与缺页

**口述：**虚拟地址分页号和页内偏移，页表映射虚页到物理页并记录权限；TLB 缓存地址翻译。TLB 未命中需查页表，页不在内存或访问权限不符可能触发缺页异常。

**机制/边界：**TLB miss 不等于磁盘 I/O；缺页可能是按需零页分配或 COW，也可能读取文件/交换空间，非法访问最终产生信号。Linux minor/major fault 的区分要结合是否需 I/O。

**追问/验证：**从地址分解画到物理页；看进程 page fault 统计与映射，别把所有 page fault 都叫程序错误。

### Q48 写时复制 COW

**口述：**多个映射先共享同一物理页并限制写权限，写入者触发异常后获得可写副本，从而避免提前复制未被修改的数据。

**机制/边界：**fork 常用 COW，MAP_PRIVATE 的文件映射也有类似私有修改语义。收益取决于后续写比例，写很多页时仍有复制与缺页成本；逻辑上独立不代表物理页立即独立。

**追问/验证：**比较 fork 后仅读和逐页写的缺页/RSS等指标，注意共享统计口径；不要只看虚拟内存大小。

### Q49 堆 栈 mmap 区

**口述：**栈承载自动对象和调用状态，堆通常由分配器管理动态对象，mmap 建立匿名或文件映射。C++ 对象生命周期与内存映射位置是不同维度。

**机制/边界：**栈上也能放指向堆的智能指针；malloc/new 不保证每次都调用系统调用，分配器有缓存/arena；大分配可能借助 mmap，阈值依分配器和配置。

**追问/验证：**递归爆栈与堆泄漏症状不同；结合 /proc/PID/maps、smaps 与对象生命周期定位，不能仅凭“地址高低”跨平台下结论。

### Q50 页缓存 mmap direct I/O fsync

**口述：**普通文件 I/O 通常经过页缓存；mmap 把文件内容映射到地址空间，访问通过缺页与缓存协作。direct I/O 常用于减少页缓存干预，但有对齐和文件系统约束。fsync 请求同步相关文件状态以支持持久性。

**机制/边界：**write 成功通常只是进入内核缓存；mmap 不是天然零开销持久存储，direct I/O 也不自动等于持久提交。目录项变更的崩溃一致性还可能要求同步父目录。错误返回、硬件缓存与文件系统语义都需考虑。

**追问/验证：**说明数据库为什么区分缓冲池脏页与日志刷盘；压测区分页缓存命中、冷读和真正同步写，不把热缓存测速当磁盘速度。

### Q51 fd file inode dentry

**口述：**fd 是进程表中的整数索引，指向内核打开文件对象；打开对象维护偏移和状态等，inode 表示文件元数据，dentry 关联路径名与 inode。

**机制/边界：**dup 和 fork 后的描述符可能共享打开文件对象和偏移；不同 open 可以有独立偏移。硬链接是多个目录项指向同一 inode，软链接保存路径。unlink 删除名字，有打开引用的文件数据可继续存在。

**追问/验证：**日志被删除后磁盘仍满，检查 `lsof +L1` 和打开 fd；不要认为删除文件名就立刻释放所有空间。

## I/O 与排障 Q52–Q57

### Q52 阻塞与同步是不是一回事

**口述：**阻塞/非阻塞关注调用缺乏进展条件时是否等待；同步/异步关注操作的完成由谁推进和如何通知。非阻塞 socket 仍由应用反复发起读写，不自动变为完成式异步 I/O。

**机制/边界：**epoll_wait 可以阻塞等待就绪，但受监视 socket 可以非阻塞；“事件循环”也不是“每个系统调用都不阻塞”。具体 AIO、io_uring、IOCP 要分别讨论 API 与实现。

**追问/验证：**画等待数据、拷贝数据、回调三个阶段，指出事件通知在何时发生。

### Q53 select poll epoll

**口述：**select 使用 fd 集合，常见实现受 FD_SETSIZE 等限制；poll 用数组避免同样的位图限制，但每次仍需提交/遍历集合；epoll 在内核维护关注集合并返回就绪事件。

**机制/边界：**epoll_wait 返回 k 个事件仍需处理 k 项，不可笼统说整体永远 O(1)。小规模/高活跃比例场景优势未必明显，平台支持不同。

**追问/验证：**用连接数、活跃比例、每事件工作量说明比较条件；网络 Q71 进一步讲异步建连结果判断。

### Q54 LT ET 的读写循环

**口述：**LT 通常在条件持续满足时继续通知；ET 不保证保留数据时重复提醒，常用非阻塞 fd 处理到 EAGAIN。事件可合并，也可能由新到达数据再次触发，不要依赖下一次提醒来处理已留数据。

**机制/边界：**读要处理 EOF/EINTR/EAGAIN，写要保存剩余字节和偏移；输出队列空时取消可写关注。ET 下若为公平性在读到 EAGAIN 前耗尽处理配额，应把该连接保留在应用级就绪队列中，后续轮转继续处理，而不是只等待新的 epoll 通知；处理到 EAGAIN 后再解除相应就绪标记。多线程操作同一 fd 还需明确连接所有权与同步。非阻塞不保证一次得到完整应用消息。

**追问/验证：**构造比单次缓冲大的输入和慢读客户端，观察是否停滞、忙轮询或内存增长。

### Q55 零拷贝减少什么

**口述：**要先画具体路径，再说减少用户态和内核态之间哪一次复制、哪些 syscall。sendfile 可从文件向 socket 转发而不先读入用户缓冲；mmap 让应用直接访问映射页，但仍有地址翻译、缺页和设备传输。

**机制/边界：**“零”通常不是系统内完全没有任何拷贝；TLS、压缩、用户态加工和网卡能力会改变路径。DMA 由硬件搬数据，不代表没有数据搬运。

**追问/验证：**对照 syscall、CPU 和吞吐，在同样缓存与数据规模下比较；只看总时间难以证明拷贝减少。

### Q56 死锁四条件和预防

**口述：**互斥、持有并等待、不可抢占、循环等待共同构成经典死锁条件。工程上常用全局锁顺序避免环，减少持锁范围，避免锁内等待外部慢操作。

**机制/边界：**超时只是打断等待的手段，还要定义状态回滚；try_lock 重试可能活锁；读写锁升级也可造成环。数据库可以检测等待图并回滚牺牲事务，普通内存锁不自动具有事务回滚能力。

**追问/验证：**画线程到锁的等待关系，使用线程栈证实；修复后对相反调用顺序和退出流程回归。

### Q57 Linux 服务排障

**口述：**先确定影响窗口、目标进程、错误率和延迟，再按 CPU、内存、I/O、锁、网络逐层取证。指标与日志共用时间范围，用假设和反证缩小范围。

**机制/边界：**top/pidstat 看线程负载，perf 找热点，strace 看系统调用，lsof 与 /proc 看 fd/映射，ss 看连接。工具可能需要权限并影响进程；先轻量采样，避免无边界采集。

**追问/验证：**“CPU 不高但 P99 高”可来自锁等待、下游、磁盘或连接池排队。给出具体指标支持，不把低 CPU 等同于系统空闲。

## 三道计算题

1. 32位虚拟地址、4 KiB页：偏移12位，页号20位；单级页表每项4 byte时大小为4 MiB。多级页表可按使用情况分配，不代表理论地址空间缩小。
2. TLB 查询10 ns、内存100 ns、命中率95%，单级页表、串行查询、无缺页：EAT=`0.95*(10+100)+0.05*(10+100+100)=115 ns`。多级页表或并行查询需换模型。
3. 3个物理页框，初始空，访问序列 `1,2,3,1,4,2,5`：LRU 共6次缺页。前三次装入，1命中；4淘汰2，2淘汰3，5淘汰1。写出每一步顺序而非凭直觉猜。
