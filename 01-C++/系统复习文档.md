## 1 类型、表达式与行为分类

先区分四件事：变量的声明类型、表达式的类型、表达式的值类别、对象的实际寿命。`int x;` 中 x 的类型是 int，但表达式 x 是左值；`std::move(x)` 是指向同一对象的 xvalue，并未搬走任何数据。引用是别名语义，指针是可存储、可为空的值，二者都不自动延长任意被指向对象的寿命。

`const int* p` 限制通过 p 修改目标，`int* const p` 限制 p 本身重新指向。顶层 const 不意味着指向的数据也只读。const 成员函数通常限制通过 this 修改非 mutable 成员，但不保证线程安全；mutable 缓存仍需同步。

| 概念 | 要回答的边界 | 小例子 |
| --- | --- | --- |
| 整数溢出 | 有符号溢出是 UB，无符号按模运算 | 判断容量加倍前是否超过类型上限 |
| sizeof | 结果是类型大小，不是动态数组长度 | 函数参数 `int a[]` 已调整为指针 |
| auto | 常按值推导，可能去掉引用和顶层 const | `auto x = ref` 可能复制对象 |
| decltype | 依表达式形态推导，括号可能改变结果 | `decltype(x)` 与 `decltype((x))` |
| constexpr | 函数具备常量求值可能性，不代表每次编译期执行 | 实参来自运行期仍可普通调用 |
| consteval / constinit | C++20；前者约束立即调用，后者约束静态初始化 | constinit 不等于 const |

行为分类要先于“预测输出”：良构程序仍可能含 UB；实现定义行为要求实现说明选择，未指定行为允许多个结果且未必说明，UB 则不受正常语义保证。一次编译运行只能提供该环境的观察，尤其不要用它证明越界、悬空或 data race 的结果。

面试追问：`size_t` 与 int 比较为何可能出现负数变巨大值？关键是通常算术转换，不是 CPU 算错。混用前检查范围与符号，别用强制转换掩盖输入约束。

## 2 存储与对象生命周期

存储期描述内存何时存在；生命周期描述某个对象何时可按其类型使用。`malloc` 分配原始存储，`new T(...)` 表达式还涉及 T 的构造。`delete` 表达式析构对象并释放相应存储；new/delete、new[]/delete[]、malloc/free 要匹配。

自动对象通常在退出作用域时析构，包括异常展开；动态对象依所有权协议释放。堆、栈是常见实现位置，不是 C++ 对所有对象布局的统一规定。局部指针变量结束寿命并不会自动释放其指向的动态对象。

典型悬空链：函数创建局部 string -> 返回 string_view -> 局部 string 析构 -> 调用方读取 view。view 不拥有字符，生命周期必须由调用契约保证。同类风险包括异步 lambda 捕获局部引用、容器扩容后保留元素地址、对象销毁后回调使用 this。

初始化顺序：虚基类、直接基类、按声明顺序的成员、构造函数体；不是成员初始化列表的书写顺序。析构大体反向。资源相互依赖时，成员声明顺序影响构造和清理的正确性。

数据库项目映射：PageGuard 的寿命应覆盖使用页数据的区间；Guard 提前析构后仍保存裸指针，可能遇到页被替换或重用。面试画出“fetch/pin -> latch -> 访问 -> unlatch -> unpin”的所有权路径，并以具体接口顺序为准。

## 3 RAII 与异常安全

RAII 把资源所有权交给对象，构造建立不变量，析构释放资源。资源不限内存，也包括 fd、锁、事务上下文和临时文件。Rule of Zero 是让现有 RAII 成员承担管理；手动管理裸资源时才认真设计析构、拷贝与移动的组合。

| 保证 | 含义 | 设计办法 |
| --- | --- | --- |
| 不抛异常保证 | 操作不会以异常形式失败 | 析构与真正可靠的清理路径 |
| 强保证 | 失败时外部可见状态不变 | 先构建临时结果，成功后提交 |
| 基本保证 | 失败后不泄漏、不破坏不变量 | 容许部分值改变，但对象可继续管理 |
| 无保证 | 失败后状态和资源不可依赖 | 需要重新设计关键边界 |

`noexcept` 是契约而非“自动处理异常”：异常逃出 noexcept 函数会终止程序。声明移动为 noexcept 可能帮助容器选择移动路径，但只能在实现确实符合时声明。

智能指针先看所有权：unique_ptr 独占且可转移；shared_ptr 共享控制块与最后一个强引用释放；weak_ptr 观察但不增加强引用，使用前 lock。shared_ptr 的引用计数线程安全不等于被管理对象字段线程安全，也不等于对同一个 shared_ptr 变量的无同步写入安全。

循环引用例：A 强持有 B，B 强持有 A，外部引用释放后强计数仍非零。把不承担生命周期的反向关联改成 weak_ptr，而不是定时调用 reset 碰运气。`make_shared` 常合并分配，但弱引用长期存在可能使合并存储留存；自定义 deleter、较大对象和生命周期要求影响选择。

## 4 拷贝、移动与完美转发

移动构造不是“把对象内存 memcpy 一遍”，而是由类型定义如何转移资源并维持源对象契约。标准库多数移后对象有效但状态未指定，具体类型可能承诺更强结果，例如 unique_ptr 移走后为空。自定义类型应明确可执行哪些操作。

`std::move` 只是转换；是否实际移动由重载决议和类型能力决定。const 对象经 move 后常得到 const T&&，常见 T(T&&) 不接收它，因此可能拷贝。不要为了显示“高性能”给所有表达式加 move。

返回值优化需分两层：C++17 某些同类型 prvalue 直接构造目标是保证语义；命名局部对象的 NRVO 仍有条件。`return local;` 通常是合适写法，`return std::move(local);` 可能阻止 NRVO。返回悬空引用不会被优化成正确对象。

转发引用是在特定推导语境中的 T&&，不是所有 &&。引用折叠中只要组合中含左值引用，结果为左值引用；全为右值引用才折叠为右值引用。命名参数表达式自身是左值，`std::forward<T>(arg)` 按推导类型恢复调用方值类别。

练习：解释模板 `f(T&& x)` 分别收到 int 左值、const int 左值、int 临时值时 T 和参数类型；再对比类模板固定 T 后的非推导 T&&。答案见 [Q11](面试题详解.md#q11)，先画类型再查。

## 5 多态、接口与对象模型

虚函数支持通过基类接口按动态类型调用；vptr/vtable 是常见 ABI 实现，不是标准强制的唯一布局。对象大小、虚表位置和多继承偏移依平台，面试可以解释典型实现但要标注条件。

通过基类指针 delete 派生对象时，普通多态接口通常需要虚析构；另一种接口设计是受保护的非虚析构，禁止外部经基类删除。对象切片发生在把派生对象按值复制到基类对象时，保留下来的只有基类子对象状态。

| 转换 | 典型用途 | 风险检查 |
| --- | --- | --- |
| static_cast | 编译期已知转换、受约束的上行/下行 | 下行必须有真实动态类型依据 |
| dynamic_cast | 多态类型运行时检查 | 指针失败返回空，引用失败抛异常 |
| const_cast | 调整访问路径的 cv 限定 | 真正 const 对象仍不允许修改 |
| reinterpret_cast | 底层表示/接口适配 | 不豁免对齐、类型访问和生命周期规则 |

优先用窄接口明确所有权和失败：借用对象传引用或观察指针，转移独占所有权传 unique_ptr，需要共享寿命时才用 shared_ptr。虚函数、模板、函数对象是不同的可扩展手段，不存在永远更快或更好的一个。

## 6 STL 选型与失效规则

| 需求 | 常用结构 | 代价与边界 |
| --- | --- | --- |
| 连续遍历、下标访问 | vector | 中间插删线性，扩容可能使全部元素地址失效 |
| 两端插删 | deque | 分段存储；不同操作的引用与迭代器失效规则要分别查 |
| 已知节点位置的频繁拼接 | list | 节点开销和局部性差，查找仍线性 |
| 有序键与范围查询 | map/set | 通常对数查改，常见实现为平衡树 |
| 精确键查找 | unordered_map/set | 平均常数、最坏线性，rehash 与碰撞有成本 |
| 最值候选 | priority_queue | 取顶常数，入出堆对数，任意删除不直接支持 |

vector 的 size 是已构造元素数，capacity 是无需重新分配的容量。reserve 只保证容量至少到要求值，不创建可按下标访问的新元素；resize 改 size，新增元素会构造。push_back 均摊常数不表示每次常数，单次扩容可线性。

失效必须回答“哪个操作、是否重分配、哪个位置”。vector erase 后被删位置及之后的迭代器、引用和指针失效；未重分配插入也会影响插入位置及之后。unordered_map rehash 使迭代器失效，但未删元素的引用/指针通常保持有效。list 删除通常只影响被删元素。

容器内外关联是项目常见陷阱：哈希表保存 vector 元素指针，vector 扩容时关联悬空；LRU 用 list 节点迭代器配合哈希表则需保证淘汰时同时移除映射。并发访问应保护跨容器不变量，不只给单次 map 操作加锁。

排序比较器必须严格弱序，`a <= b` 破坏自反相关要求。emplace_back 可就地构造，却不保证总胜过 push_back；参数可读性、构造副作用和重载行为也要考虑。

## 7 模板、编译与链接

典型链路：预处理展开头文件与宏 -> 编译为目标代码/汇编 -> 汇编产生目标文件 -> 链接解析符号和重定位。头文件不是链接时自动加载的模块，重复定义与缺失定义是不同问题。

模板通常要求实例化点可见定义，因此常写在头文件；也可控制显式实例化并分离定义。ODR 约束程序中的定义，inline 不仅是性能提示，它还涉及允许跨翻译单元定义的规则。模板链接失败先核对定义可见性、实例化类型和链接目标。

静态库通常按需要把对象代码并入最终程序；动态库引入运行时加载、符号解析、部署和 ABI 兼容边界。C++ ABI 还涉及编译器、标准库、异常和运行库配置；“接口签名一样”不证明任意二进制可互换。

CMake 面试应说明 target 的 include、compile features 和依赖传播。PRIVATE/PUBLIC/INTERFACE 管理使用需求，避免把所有目录和参数做成全局状态。生成成功、编译成功、链接成功、测试通过是四个不同阶段。

## 8 线程同步与内存模型

data race 是不同线程中冲突访问、至少一次写、至少一侧非原子且缺少适当 happens-before 的语言问题；一般 race condition 则是结果依赖交错造成逻辑错误，可能在全部使用原子变量时仍存在。

mutex 既提供互斥，也通过相应解锁/加锁建立可见性。release/acquire 需要读取相应发布值等条件才建立同步，不是只要两处出现单词就成立。relaxed 提供该原子对象的原子性和修改顺序，不发布旁边的普通对象。

```text
发布线程：初始化 payload -> ready.store(true, release)
接收线程：ready.load(acquire) 读到 true -> 读取 payload
前提：对象持续存活；发布后不再无同步修改 payload
```

seq_cst 为相关顺序提供更强约束，但不自动把多个原子操作组成事务。volatile 不替代线程同步。CAS 失败要更新预期值并正确重试；ABA 关注值恢复后对象身份或历史已经变化，还可能需要版本号和内存回收协议。

条件变量通知不保存事件计数：共享谓词在同一同步协议下更新，wait 用谓词循环重查。醒来可能是虚假唤醒，也可能资源已被其他消费者拿走。通知放在锁内或锁外取决于寿命与时序设计，单独改变通知位置不修复状态协议。

<a id="cpp-9"></a>
## 9 队列、线程池与关闭协议

有界队列需要明确容量、生产者等待、消费者等待、关闭与异常。常见状态 running -> closing -> stopped；关闭后是否排空已有元素是契约，不是实现时临时决定。

```text
push: 持锁等待 closed 或 size < capacity
      closed 则拒绝，否则入队并通知消费者
pop:  持锁等待 closed 或非空
      非空则取元素；closed 且空则返回结束
close: 持锁设置 closed；唤醒两类等待者
```

异常边界：元素移动抛异常时，队列是否仍满足不变量？析构前谁保证所有线程离开等待？关闭是否幂等？停止与提交如何线性化？先回答这些，再讨论无锁结构。

线程池取出任务后释放队列锁，再执行任务。任务异常应到达 future 或显式错误通道，避免逃出线程入口终止进程。工作线程自己 join 自己、满池任务各自等待同池新任务，都是需要设计规避的死锁情形。

项目映射：数据库 buffer pool 的 pool 是页框管理，不等于线程池；网络连接池、对象池和内存池也各自管理不同资源。面试先给资源、容量、所有权和归还规则。

## 10 性能与调试证据

按症状选工具：ASan 查许多内存越界与寿命问题，UBSan 查覆盖范围内的 UB，TSan 查数据竞争；检测器有平台限制和运行开销，未报错不证明绝无问题。GDB/LLDB 用栈、断点、watchpoint、线程状态定位；core dump 还需要匹配二进制与符号。

性能先定义工作量和正确性，再测 throughput、p50/p95/p99、错误率、CPU、内存与锁等待。局部循环变快可能增加分配或尾延迟；热缓存和冷启动不能混为一组样本。

伪共享是不同热点变量位于同一一致性块导致争用，未必有 data race。只对数组开头 alignas 不保证每个元素分离；检查元素大小、布局和硬件。比较同负载的紧邻/隔离布局并测缓存行传输，不能仅凭 CPU 高判定。

## 11 综合推演与实验

**案例一：异步回调悬空。**函数局部 string 被引用捕获，任务排队后函数返回。根因是被借用对象先结束寿命；按值捕获或持有明确所有权可以修复此路径，但仍要考虑任务取消、对象体积和循环引用。验证不依赖“很快执行就没事”，应主动延迟任务触发。

**案例二：reserve 的误用。**空 vector reserve(100) 后写 v[0]，size 仍为零，访问越界。改为 resize 创建元素或 push_back 插入。要求解释内存容量与对象构造两个层次，而不只背 API 名。

**案例三：错误的停止标记。**工作线程循环读普通 bool，主线程写 true；即使 bool 的机器写看似不可分，也缺少语言层同步。可用 mutex+cv 或正确原子协议，且仍需 join 保证对象寿命。

建议实验清单，以下是待执行练习而非本仓库已有成绩：

| 练习 | 预测与观察 | 验收 |
| --- | --- | --- |
| 构造/拷贝/移动计数 | 区分 C++17 prvalue 与命名局部返回 | 不把可选 NRVO 次数当固定标准输出 |
| vector 与哈希 rehash | 先判断哪些引用有效，不主动解引用悬空值 | 用规则与实际地址记录分开解释 |
| 有界队列关闭 | 空队列消费者、满队列生产者、同时 close | 全部线程退出，关闭后提交有明确结果 |
| 异常注入 | 在第 N 次资源申请或元素操作抛异常 | 不泄漏且不变量成立，记录保证等级 |

## 12 复习计划、面试自测与参考

七次训练：类型与寿命；RAII；移动与转发；容器；编译链接；同步；队列与性能。每次先读本页对应章，再闭卷答两题，最后去逐题详解核对。重点不是读完，而是能解释一个失败输入。
