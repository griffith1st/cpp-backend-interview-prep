## 1 项目事实与贡献边界

面试不是把技术栈逐个背定义，而是证明你做过什么、为什么这样做、如何知道它正确。准备材料分成四层：简历陈述、源码实现、实际测试、运行或业务结果。源码有函数不等于函数被调用，测试文件存在不等于测试通过，单测通过不等于线上稳定。

| 类别 | 推荐表述 | 需要准备 |
| --- | --- | --- |
| 框架已有 | 基于框架使用/理解某能力 | 调用链与配置，不归为从零实现 |
| 本人实现 | 修改了某模块并维护某不变量 | diff、函数、正常与失败分支 |
| 本人验证 | 复现/调试/补测试验证了某行为 | 命令、输入、实际输出、版本 |
| 阅读推演 | 阅读源码并分析可能边界 | 标记推演，提供验证方案 |
| 未来设计 | 下一步建议采用某机制 | 理由、成本、验收与回滚 |

若历史材料相互矛盾，先核对版本，不选择更好看的数字。族谱案例中的 10 万级成员、30 代是模拟数据规模；课程项目与参考框架不能自动变成真实生产经历。AI 帮助组织语言，也应保留贡献和执行证据边界。

## 2 讲清架构与请求链

一张模块图回答谁依赖谁，一条请求链回答数据如何流动，两者不等价。每个箭头需说明协议/函数、输入输出、是否同步、错误如何传播。跨线程、进程、数据库的边界尤其容易藏状态丢失。

```text
入口 -> 鉴权/解析 -> 业务或计划 -> 核心数据结构 -> 持久化 -> 响应
          错误分类、超时预算、trace、事务与资源所有权贯穿链路
```

对关键对象写生命周期：谁创建、谁拥有、谁借用、何时释放、取消后谁清理。对关键状态写合法跃迁：例如事务 active -> committed/aborted，不允许已经提交后继续修改原写集。

面试讲接口不止参数类型，还包括前置条件、后置条件与异常保证。返回空指针、抛异常、返回错误码都可以，但调用方必须有清晰处理协议；混用而忽略分支会破坏系统不变量。

## 3 RMDB 数据库项目深挖

典型教学链路为 Parser/AST -> Analyze -> Planner -> Portal/Executor -> Record/Index -> BufferPool -> Disk，事务、锁与日志横跨多层。以实际版本定位，不假设所有课程框架都实现相同接口。

### 3.1 缓冲池

page_id 是持久页标识，frame_id 是内存槽位。page table 管映射，pin 计数约束替换资格，dirty 表明页有未持久化修改。fetch 命中后增加引用，未命中寻找空闲或可替换页框；替换脏页前满足写回条件，随后装入新页并更新映射。

不变量：一个有效页映射到正确帧；pinned 页不被淘汰；重用帧时旧元数据清理；读取失败不留下看似有效的映射。测试全 pin、重复 fetch/unpin、脏页替换、页不存在和 I/O 失败，而不是只测一次正常读。

### 3.2 记录与执行器

槽位/位图决定哪些记录存在，RID 连接页与槽。insert/delete/update 同时影响计数、位图与数据；异常后保持它们一致。执行器迭代接口要定义 begin/next/end、空输入和输出 schema，join/aggregation/sort 的内存和类型转换是常见追问。

### 3.3 索引、事务与恢复

标准磁盘 B+ 树关注页布局、分裂合并、父指针、叶链与根变化；如果个人版本只是进程内有序容器并从基表重建，应如实说明，而不是拿标准 B+ 树名字替换实现。存在优化器接口也不说明已经有代价优化。

恢复回答从日志记录了什么、何时持久、如何识别已提交事务、崩溃重启如何扫描开始。基础 committed redo/active undo 不等于完整 ARIES；ARIES 的分析、重做、撤销、LSN、CLR、检查点等需要实际机制支撑。

这些边界来自此前复习材料所描述的教学版本，不是宣称所有 RMDB 分支相同。持有个人源码时，应复核当前 commit 后再用于简历答辩。建议主讲一个真实改动，加一个边界测试，而非泛讲整套数据库。

## 4 Muduo 与网络课程项目

Muduo 阅读线：EventLoop 管线程内循环，Poller 获取就绪，Channel 封装 fd 事件，TcpConnection 管连接与缓冲。one loop per thread 是归属约束，不代表每条连接各一个线程；跨线程投递需队列与唤醒机制。

网络项目四个不变量：应用消息完整后才解析；短写保留剩余字节；回调使用对象时对象仍存活；队列内存有上限。高水位回调只是通知，应用需决定暂停上游、拒绝、丢弃可丢消息或关闭慢连接。

邮件课程案例可从 POP3 状态机讲：AUTHORIZATION -> TRANSACTION -> UPDATE；DELE 成功只是标记，正常 QUIT 进入提交删除阶段，连接异常需确认结果。跨会话序号可变，缓存与删除应按账户/服务器范围的 UIDL 重新对应当前序号。

个人课程报告曾区分 POP3 与 SMTP 分工，因此答辩应以自己的实际模块为主，团队协议仅说明联调。具体行协议、点转义、TLS 和测试矩阵见[网络完整版第 19 章](../04-计算机网络/系统复习文档.md#19-你的邮件客户端课程设计专项)，原报告不随仓库发布。

## 5 后端应用与中间件

ITMS 类型链路可从前端 HTTP/JSON、JWT Filter、Controller、Service、Repository 到 PostgreSQL，再说明 Redis/Kafka/WebSocket 的实际使用点。依赖存在不证明业务路径启用；现场先指出调用者、键/主题与错误分支。

Spring 事务回答传播、隔离与代理边界，远程调用或 Kafka offset 不会因为某个本地注解就与数据库原子提交。JPA 关注 N+1、懒加载、SQL 与事务范围，不用 ORM 抽象掩盖实际查询成本。

Flask 默认 session 可是签名 Cookie，不等于所有会话都存服务端。保护密钥与属性，签名不加密内容；清当前浏览器 Cookie 不保证旧副本即时撤销。数据库连接池需归还、超时与事务清理，异常也应释放连接。

Compose 中服务名解析、容器端口与宿主机端口分开，localhost 通常指当前容器。依赖启动与服务就绪不同；健康检查可参与启动条件，但运行期故障仍靠重试、限流与可观测性处理。

汽车测试实习可讲需求编号、信号定义、刺激输入、Trace 实际报文、判定、缺陷与回归。CAN ID 与字节序要解释清楚，测试参与不自动等于设计整车算法；不发布工作中的私密 trace 或凭据。

## 6 构建、依赖与版本

可复现构建至少记录源码 commit、子模块 commit、编译器、标准库、构建选项与依赖版本。Debug/Release 差异、断言是否开启、Sanitizer 是否启用都会改变结果。构建目录与源码目录分离，避免生成文件污染源码。

```bash
cmake -S . -B build-review -DCMAKE_BUILD_TYPE=Debug
cmake --build build-review -j 2
ctest --test-dir build-review --output-on-failure
```

以上仅适用于提供 CMake/CTest 的项目，且是待执行命令示例；多配置生成器通常还要传 --config。先读真实项目 README，不把示例命令写成所有项目通用且已经通过。

错误定位按阶段分：配置发现依赖失败、编译语法/类型错误、链接未定义符号、加载动态库失败、运行断言、测试结果错误。检查首个根因而不是只修最后一屏连锁报错。

<a id="project-7"></a>
## 7 测试与故障复现

单元测试验证局部契约，集成测试验证边界协作，端到端验证用户链路，性能测试验证给定负载下的资源与时延。数量多不等于覆盖关键不变量，尤其要覆盖失败与并发交错。

测试设计从输入等价类、边界、状态迁移和错误注入出发。修复前相同输入失败、修复后通过，再跑相关回归；如果缺少修复前证据，就诚实标记当前检查，别回填历史结果。

| 类型 | 例子 | 应保存的证据 |
| --- | --- | --- |
| 正常 | 一条 SQL 或一个完整请求 | 输入、期望、实际输出 |
| 边界 | 空表、全 pin、最大消息、容量 0 | 约束与错误路径 |
| 并发 | 提交与关闭交错、读后写竞争 | 时序、同步点、可重复触发条件 |
| 故障 | I/O 失败、超时、响应丢失 | 已提交/未提交/未知的分类 |
| 回归 | 关联路径保持原行为 | 版本、命令、退出码和失败摘要 |

mock 隔离不稳定依赖，但可能隐藏真实协议差异；契约测试和少量真实集成测试可补足。随机测试保存种子，等待用条件/超时而不是无上限 sleep。测试数据与凭据隔离，清理只针对本次创建的资源。

## 8 调试与性能分析

故障流程：复现 -> 最小化 -> 提出候选 -> 收证据 -> 排除 -> 修复 -> 回归。不同假设要有能区分它们的检查；反复“加日志看看”却不说明要观察哪个状态，效率很低。

崩溃检查线程栈、异常/信号、对象寿命；挂起检查所有线程等待与锁顺序；错误结果检查不变量与最早偏离点；尾延迟检查排队和下游而不只 CPU。工具选择依平台，调试开销与符号质量也应记录。

优化前定义固定数据集与负载。吞吐提升 20% 但错误率上升不算同等工作完成得更快；平均时延下降而 P99 上升需解释用户影响。重复多轮并报告波动，不只挑最好一轮。

测量表至少包含版本、机器、编译配置、数据规模、访问分布、并发或到达率、持续时间、吞吐、p50/p95/p99、错误、CPU/RSS 与瓶颈证据。没有实际测量就给方案，不能把预期收益填成成绩。

## 9 Git、评审与发布

先读 status/diff，确认已有未提交改动归属；提交围绕一个可解释变更，避免夹带配置、凭据和构建产物。子模块记录固定提交，普通主仓库 clone 不保证下载全部子模块，复现说明需包含初始化步骤。

revert 用新提交反向撤销已发布改动，reset 改引用/索引/工作区，二者影响协作历史不同。共享分支避免随意重写历史；冲突解决先理解双方意图，不以“取我这边”替代合并。

代码评审优先正确性、数据与资源生命周期、异常、并发、兼容与测试，再看风格。PR 描述写背景、行为变化、测试和风险；“重构无行为变化”也需证据支撑。

发布包含配置、数据库 schema、二进制/镜像和观测。数据库迁移应考虑旧新版本并存，expand-contract 常比一次不可逆改动更易逐步推进。回滚应用不一定能回滚已经改变的数据，必须单独设计数据修复路径。

<a id="project-10"></a>
## 10 日志、监控与运行保障

日志记录离散事件，metrics 适合聚合趋势，trace 关联一次请求链。统一时间、trace/request ID、模块与错误码，避免只留“failed”没有上下文。敏感令牌、完整邮件或生产数据不要无差别写日志。

告警围绕用户症状和可行动性：错误率、尾延迟、资源饱和，再补核心不变量和积压。健康探针区分存活、就绪与启动；依赖慢不应无条件让全部实例同时重启。

优雅退出先停止新流量，标记关闭并唤醒等待者，在 deadline 内处理在途工作，之后按契约中止并释放。日志最后一行正常不证明后台任务全部结束，线程与连接生命周期需要实际确认。

## 11 三种答辩案例

### 11.1 结果被截断

现象是大查询结果不完整。候选包括执行器提前结束、格式化缓冲限制、单次 write/recv。用输出记录数、序列化长度、发送返回值、接收累积长度分层定位。若网络短写被证实，修复发送偏移和 framing，并覆盖拆分/合并、超长输入、慢读与关闭。此处是训练推演，只有自己的实际日志才能作为曾修复案例。

### 11.2 缓冲池淘汰错误

构造容量很小的池，pin 某页，持续访问其他页；若仍能被替换，检查 pin 更新与 replacer 候选集合是否在一致同步边界。修复应维护跨结构不变量，并测试异常路径是否遗漏 unpin。不得为了让测试过而简单禁用全部替换。

### 11.3 数据库连接池耗尽

低 CPU、请求排队、活跃连接长期满。候选是连接泄漏、长事务、慢 SQL、锁等待或池配置。关联借用归还日志、事务时长与数据库活动；修复后检查异常时归还、超时和可承受并发，而不只把池扩大。

## 12 面试讲稿与训练计划

两分钟：背景一句、职责一句、一条链路、一个难点、一个实际证据与一个限制。十分钟加入状态图、失败分支和取舍；三十分钟准备并发、持久化、性能与演进。所有模板里的数字都由真实结果填写。

```text
项目 / commit / 构建环境：
我负责与框架已有：
入口 -> 关键函数 -> 输出：
两个不变量与一个失败路径：
复现输入 / 修复前结果 / 修复后结果：
性能测量口径与实际值（未测则留空）：
当前限制 / 下一步 / 验收与回滚：
```

一周每天准备一个产物：事实清单、调用链、数据结构、故障最小复现、性能/测试记录、未来改进、30 分钟模拟。用 [P10 项目追问](../09-AI学习/提示词库.md#p10-项目证据追问)要求 AI 定位证据缺口，不生成不存在的实现经历。

参考：[CMake 官方教程](https://cmake.org/cmake/help/latest/guide/tutorial/index.html)、[Git 文档](https://git-scm.com/doc)、[GoogleTest Primer](https://google.github.io/googletest/primer.html)、[GDB 手册](https://sourceware.org/gdb/current/onlinedocs/gdb.html/)、[OpenTelemetry 概念](https://opentelemetry.io/docs/concepts/)。外部入口用于进一步核对，具体命令需适配项目版本。
