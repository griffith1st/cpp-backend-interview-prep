## 项目选择

主项目只选一个深挖，另选一个作为补充阅读：

| 路线 | 主讲内容 | 本地入口 |
| --- | --- | --- |
| RMDB | 存储、缓冲池、执行器、索引、事务、恢复 | [项目答辩与证据手册](项目答辩与证据手册.md#rmdb-数据库内核) |
| Muduo | Reactor、事件循环、连接生命周期、缓冲、线程模型 | [源码](../repos/chenshuo-muduo/muduo) |
| BusTub | 页/缓冲池、B+ 树、执行器、优化、并发控制 | [源码](../repos/cmu-bustub/src) |

不要同时把三个项目都包装成“自己实现”。源码阅读项目应明确说“阅读、重写练习、测试验证”的范围。

## 每个项目必须产出

1. 一张模块图和一张核心请求调用链。
2. 三个核心数据结构及其不变量。
3. 一个并发或失败状态机。
4. 两个真实 bug/边界问题及定位证据。
5. 一组构建、单测、压力或性能结果。
6. “当前实现 vs 标准实现”的边界清单。
7. 2 分钟、10 分钟和 30 分钟三版讲稿。

## Muduo 建议主讲点

- one loop per thread 的线程模型。
- EventLoop、Poller、Channel 的协作与线程归属。
- accept、连接建立、读写事件、缓冲、关闭的完整生命周期。
- output buffer 与高水位回调如何处理慢客户端和背压。
- timer、wake-up fd、跨线程任务投递。

实验：给 EchoServer 加连接数、消息数、排队字节指标；构造慢读客户端观察高水位行为。

## BusTub 建议主讲点

- PageId、frame、page table、pin、dirty 和替换器。
- PageGuard 如何用 RAII 管理 pin/unpin 和锁。
- B+ 树查找、插入、分裂、删除、合并和并发访问。
- Volcano executor、Hash Join、Aggregation、TopN 与优化规则。
- 事务状态、锁表、死锁检测和回滚。

实验：先读测试再读实现；为缓冲池淘汰、B+ 树边界和执行器空输入补测试。

## 工具链

- 构建：CMake target、Debug/Release、编译数据库、依赖边界。
- 质量：clang-format、clang-tidy、警告全开、单元/集成测试。
- 正确性：ASan、UBSan、TSan、Valgrind（Linux）。
- 调试：GDB、core dump、断点、watchpoint、线程栈。
- 性能：基准、perf、火焰图、CPU/内存/锁/I/O 指标。
- 运行：日志级别、结构化日志、metrics、trace、健康检查、优雅退出。

## 一次真实故障的回答结构

```text
现象和影响 -> 如何复现 -> 初始假设 -> 收集的证据
-> 根因 -> 修复方案与取舍 -> 回归测试 -> 监控/预防
```

面试官通常会追问：为什么测试没提前发现、是否有并发窗口、失败如何回滚、优化是否有数据、方案还有什么边界。
