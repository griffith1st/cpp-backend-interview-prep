更新：2026-09-07。适用对象：当前简历中的 RMDB、ITMS-BD 和“寻根溯源”族谱管理系统。

**本次划分：RMDB 讲数据库内核独立实现，ITMS 讲合作中的路线规划后端，族谱讲合作中的数据库与亲缘查询。** 三项分别体现 C++ 底层实现、Java 业务链路、关系数据建模与图查询，避免每项都写成“全栈独立负责”。

归属口径：本人已确认 RMDB 题目 1–11 独立完成，另两个项目为合作完成。合作项目的模块划分是本次选定的**建议方案**，用于整理、确认个人职责；源码证明功能存在，未单独证明具体作者。下文的建议分工及相应简历稿须与本人实际参与核对后使用。团队人数、他人姓名、生产指标和事故经历均不设定。

## 三项目分工总表

| 项目 | 本人定位 | 本人重点范围 | 共同参与 | 建议由其他协作者承接 / 范围外 |
| --- | --- | --- | --- | --- |
| RMDB | 基于教师框架独立完成学生题目 1–11；已由本人确认 | 页与缓冲池、记录管理、查询执行、类型扩展、功能型索引、事务锁与基础恢复 | 课程接口与框架衔接 | 教师骨架、第三方库、生成的解析文件、AI 后续修复属于各自来源 |
| ITMS-BD | 合作项目中的路线规划后端，建议主责 | 路网与三策略计算、拥堵快照读取、路线保存/历史查询、路线 API | 前端契约、交通数据接口、部署和日志定位 | 页面图表、认证、采集/Kafka、预测与信号模块、整体部署主责 |
| 族谱 | 合作项目中的数据库与亲缘查询，建议主责 | 成员/亲子/婚姻模型与约束、图加载和 BFS 查询、索引与模拟数据导入 | 成员和关系 CRUD、查询结果渲染、全局模式评审 | 账号会话、邀请协作、页面样式、整体部署主责 |

**面试投入建议：**C++ 后端方向 RMDB 50%、ITMS 30%、族谱 20%；Java 后端方向 ITMS 优先、RMDB 体现底层基础。比例是复习时间分配建议，不是历史工作量统计。

**项目排序：**当前 C++ 目标保持 RMDB → ITMS → 族谱。Muduo、BusTub 留在[源码学习路线](README.md)，不替换这三项经历，也不自动增加为个人开发项目。

## 合作时的交接边界

这里的“其他协作者”指建议职责位置，不代表已核实某位成员承担过这些工作。

### ITMS 的纵向闭环

本人建议主责从 `POST /api/routes/plan` 进入，到路线结果落入 `route_plans`、返回前端结束。规划计算读取拥堵数据，但不把数据生产和模型预测一并划入本人模块。

| 交接对象 | 对方交付 | 本人交付 | 联调必须说清 |
| --- | --- | --- | --- |
| 前端 | 起终点、策略、请求发起和结果展示 | 路口列表、路网、规划、历史接口 | 实际路由、策略枚举、距离/时间/碳排单位、失败提示 |
| 交通数据模块 | 路口/方向、时间戳、拥堵等级 | 规划所需只读 Map 与数据缺失处理 | 最新完整批次还是逐路口最新；过期和模拟回退的标识 |
| 身份模块 | 当前登录身份 | 当前用户的路线保存和读取边界 | 现实现从客户端接收 userId，身份绑定列为待完善项 |
| 部署协作 | 数据库及服务环境 | 路线冒烟步骤、异常日志、接口契约 | 服务就绪、种子数据、Spring Profile、连接配置 |

### 族谱的数据闭环

本人建议主责覆盖成员与关系数据进入数据库、加载为图、查询祖先/后代/关系路径。账号和页面由协作者主做，本人说明查询接口的参数、结果和约束即可。

| 交接对象 | 对方交付 | 本人交付 | 联调必须说清 |
| --- | --- | --- | --- |
| 页面 | 成员选择、层数、页码 | 成员/边列表、查询层级、路径结果 | 同名成员用 ID 区分，跨族谱筛选，空结果 |
| 账号与协作 | 登录态、族谱访问上下文 | 带族谱范围的数据查询 | 登录检查与资源权限分别校验；六表不等于完整 RBAC |
| CRUD 协作 | 成员和关系变更 | 表约束、查询一致性要求 | 关系变化后进程内缓存失效；当前实现尚有缺口 |
| 数据准备 | 测试环境 | 生成脚本、CSV/COPY 与核对 SQL | 模拟数据规模、失败导入、序列校正、执行计划留档 |

## 简历三段建议稿

下面不添加成绩、QPS、优化百分比或线上用户数。RMDB 按已确认归属写；ITMS 与族谱是**分工确认后使用的候选稿**。日期沿用原简历，职责调整不产生新的项目时间。

### RMDB 数据库内核实现｜独立课程实现

技术栈：C++17、CMake、GoogleTest、Linux。

- 基于 RMDB 教学框架独立完成题目 1–11 的学生实现，完成磁盘页、LRU 缓冲池与定长记录管理，贯通 SQL 分析、计划生成和执行链路。
- 扩展 BIGINT/DATETIME、聚合、排序、LIMIT 与 BNLJ；实现单列/复合唯一索引功能及范围访问，维护 DML 与索引一致性。索引为简化有序容器实现。
- 实现事务提交/回滚、锁兼容检查与 no-wait 冲突中止，接入 WAL 日志及基础 REDO/UNDO 恢复；围绕页状态、索引一致性和回滚路径准备验证证据。

最后一句只表示验证重点。已有测试结果须附原始日志后另写，勿把本次文档检查视作 RMDB 测试。

### ITMS-BD 智能交通管理系统｜合作：路线规划后端

技术栈：Java 17、Spring Boot 3.2、Spring Data JPA、PostgreSQL；Docker Compose 用于联调环境。

- 在合作项目中负责交通感知路线规划后端，围绕 14 个路口、29 条边的演示路网，组织拥堵快照读取及三种权重策略的 Dijkstra 路径计算。
- 完成路口/路网、规划与历史查询接口衔接，通过 JPA 保存路线点、路段和统计结果，与前端对齐请求参数、策略和展示单位。
- 参与 Docker Compose 环境联调，结合接口返回、服务日志和数据库查询定位路线链路问题；明确实时数据、时段模拟回退与外围预测模块的边界。

这段比现有“部署、联调与测试运维参与”更深入。若实际参与止于部署联调，应采用下一节的保留版，不直接增加算法开发归属。路线代码尚有待验证问题，正文列出，简历不声称已修复。

### 寻根溯源族谱管理系统｜合作：数据库与亲缘查询

技术栈：Python Flask、PostgreSQL 16、psycopg2；Jinja2 用于查询结果对接。

- 参与六类关系数据模型设计，重点负责成员、亲子和婚姻关系的表结构、约束与查询数据契约，协同完成成员及关系 CRUD。
- 基于亲子图组织祖先/后代的逐层 BFS、关系路径的双向搜索，以及访问去重、深度限制和结果分页；说明进程内图缓存的一致性边界。
- 围绕姓名模糊检索和亲子双向访问设计 GIN/复合索引，组织模拟族谱生成及 CSV/COPY 导入，准备执行计划与查询正确性对照。

“双向搜索”描述当前算法结构，不额外承诺所有图形下最短路径已获验证。“10 万成员、30 代”移到项目底稿的模拟数据口径，待导入统计和查询记录齐全再作为简历数字。

## 学习顺序与验收

建议集中 5 次，每次 60–90 分钟；这只是第一阶段，不替代日常算法与基础课复习。

| 次序 | 本次任务 | 留下的成果 | 验收方式 |
| --- | --- | --- | --- |
| 1 | 核对三项分工、精简简历技术名词 | 三段职责稿，每条标记参与深度 | 每条都能定位函数或交付物 |
| 2 | RMDB 存储 → 执行 → 事务恢复 | 一张 SQL 调用链，三个不变量 | 脱稿讲清一次更新及一次回滚 |
| 3 | ITMS 规划 → 快照 → 保存 | 一张请求图，一份 API 契约 | 解释权重、缺路口数据和失败路径 |
| 4 | 族谱模型 → 图查询 → 索引 | 小图手算、SQL 和缓存变化分析 | 解释环、最短路径、分页与失效 |
| 5 | 每项 30 秒/3 分钟，随机追问 | 录音、首次答案、证据缺口 | 四问都答出“代码位置 + 边界” |

每项至少备好一条正常路径、一条异常路径和一个技术取舍。代码阅读发现的问题可作为“当前识别的风险”，实际修复后再升级为“我的修复经历”。

第一阶段底稿准备状态：

- [x] 三项目定位、源码入口和建议协作边界。
- [x] 六组介绍提纲、技术选型、追问题与验证方向。
- [x] 区分现实现、历史声明和下一步方案。
- [ ] 本人核对两个合作项目的逐项参与程度。
- [ ] 按项目运行验证并保存结果；本次只做文档及源码核对。
- [ ] 完成一次不看稿的四问自测并记录首次表现。

文档交付完成与个人复习验收完成是两个状态。

## 四问脱稿检查

| 问题 | RMDB 应答关键词 | ITMS 应答关键词 | 族谱应答关键词 |
| --- | --- | --- | --- |
| 解决什么问题，你负责什么？ | 教学数据库、框架、题目 1–11 | 演示规划、本人后端范围、外围协作 | 成员/关系、数据库与查询、账号页面协作 |
| 核心请求怎样流转？ | SQL → 分析/计划 → 执行 → 记录/页 | API → Service → 快照 → 图搜索 → 保存 | 路由 → 范围检查 → 图/SQL → BFS → 展示 |
| 哪个选择最值得解释？ | LRU、BNLJ、no-wait 或基础恢复 | 固定快照、非负权重、单体/JPA | 邻接关系表、BFS/CTE、缓存与索引 |
| 问题和证据是什么？ | 页固定/回滚/恢复边界及实际记录 | 权重、批次或权限的源码风险及待测项 | 缓存陈旧、双向搜索或约束的源码风险及待测项 |

追问时先回答当前实现，再说取舍和未来改进。数据库面试里 RMDB 讲“引擎怎样实现”，族谱讲“应用怎样使用 PostgreSQL”，避免把 PostgreSQL 的 MVCC 算成自己写的内核能力。
