# 用 AI 训练到能回答而不是只看懂

本目录把原来的题库、详解、算法题单和项目证据连接成可反复执行的训练流程。适用于支持文本输入的AI助手，不绑定模型、订阅或API，也不承诺固定时间掌握全部内容。

## 三分钟启动

课程基础不连贯时，先从[七专题系统复习总目录](../系统复习总目录.md)选择当前模块长文，按章提供给 AI；已有基础时继续用原题与详解做闭卷训练。

1. 打开[提示词库](提示词库.md)，使用P0总控提示词，把目标岗位和今日时间填进去。
2. 让AI先读取仓库README、[原题库](../08-题库/高频问题.md)与[答案索引](../08-题库/答案索引.md)。普通聊天工具读不到本地文件时，只上传/粘贴本次模块原题与详解，不要以为贴GitHub URL等于它已阅读。
3. 先答题再看答案，每轮只问一题。不会时先接受一级提示，尽量独立完成推导。
4. 用原题库0–4分标准记录首次答案，提示后的答案不冒充独立完成；当天结束生成下一次可直接粘贴的学习记录。

## 哪种情况用哪个提示词

| 情况 | 提示词 | 产出 |
|---|---|---|
| 第一次使用本仓库 | P0总控、P1诊断 | 基线、今日路线、第一题 |
| 看定义但不懂机制 | P2分层讲解、P3闭卷复述 | 机制图、不变量、口述反馈 |
| 学C++总是只背语法 | P4代码推演 | 编译/运行/UB分类与边界测试 |
| 算法做题没有方向 | P5算法教练 | 逐级提示、证明、失败样例 |
| 想把OS/网络落地 | P6实验教练、P7故障推理 | 有前置条件的实验与证据链 |
| MySQL/Redis混淆 | P8并发时间线 | 两会话交错、引擎边界 |
| 系统设计只会堆组件 | P9设计面试 | 需求、计算、失败方案与评分 |
| 项目答辩容易夸大 | P10项目追问 | 贡献边界、证据缺口、讲稿 |
| 临近面试要查漏 | P11混合模拟、P12错题复习 | 不泄题的测试与变式 |
| 换聊天窗口或隔天继续 | P13学习检查点 | 可携带的进度，不依赖模型记忆 |
| 怀疑AI答案有错 | P14事实核验 | 结论分级、来源、待验证点 |

## 每天 30 分钟的最低闭环

```text
5分钟：闭卷回忆昨天2题，不先看笔记
8分钟：学习今天1个概念，解释为什么而非只背定义
10分钟：做1个变式/代码推演/时间线
5分钟：不看材料再口述，记录首次分数与错误
2分钟：生成学习检查点，安排下一次复测
```

若有90分钟，再加一道35分钟算法题和20分钟项目/实验。复测可以从第2、7天开始，答错就缩短间隔；只是复习安排，不是保证长时记忆的公式。

这是一周熟悉训练方法的路线，不替代[10周主线](../00-学习路线/10周主线.md)。不要把一周题表全部勾选为已掌握；以实际回答和复测证据决定。

## AI 输出的验收

- 每个事实能区分语言标准、OS/数据库实现、项目源码与假设。
- 阅读了什么文件要能列出实际路径/标题，没有访问就标记未读，不虚构行号。
- 代码没有执行就标为静态推演，测试没有输出就不记“通过”。
- 先提交个人答案，再显示参考解；减少识别熟悉感造成的虚假掌握。
- 失败样例、首次分数、提示级别、复测结果分开保存。
- 个人简历、日志、数据库和邮箱资料先去除凭据及不必要个人信息，不上传完整生产数据。

原仓库的[进度看板](../00-学习路线/进度看板.md)只由学习证据推动，不由AI为了配合你而自动勾选。
