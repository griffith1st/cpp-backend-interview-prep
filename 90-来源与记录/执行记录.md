此前出现的“请求参数无效”不是 GitHub clone、PowerShell 命令或 `Pre` 创建失败：

2. 工具返回后，Codex 客户端自动发起下一次模型续写请求（`POST HOST/v1/responses`，模型续写阶段）。
3. 上游返回 HTTP 400 `invalid_request_error`，`param` 为空；因此当时没有继续执行后续克隆和文件写入。
4. 重新拆分请求后，目录创建、10 个仓库克隆和文档写入均已完成。

结论：错误发生在模型服务的续写请求格式/兼容层，和本地 GitHub 请求无关。若再次出现，先查看当前工具是否已经返回结果，再从最后一个已验证步骤继续，不要重复克隆成功的仓库。
